AFTER HUMAN · The As-Received Web · Edition 01

Ask two of nineteen sites for the markdown version and you get 200 OK and 471–718KB of HTML.

A dated snapshot of what 19 live sites actually handed to an agent on 18 October 2026. Measured, method published, raw data included. No scores. No rankings.

What this is. On 18 October 2026 we requested the same pages three ways and recorded what came back. This edition reports those responses. It is a record of the response layer, not of what any agent did with it.

What this is not. Not an AI visibility index, not a score, not a ranking, not a claim about agent behaviour or purchases. §8 lists every claim this report refuses to make.

Read these five lines before the numbers

  • Entry URLs only. We measured homepages. Product detail pages are a different population and are not characterised here.
  • No JavaScript. We did not render pages. In a browser, forms and content may be visible that an HTTP fetch never receives.
  • One run, one date. k=1. There is no time series in this edition.
  • Convenience sample. 20 hosts, chosen by category, not randomly drawn. Percentages describe this sample, not the web.
  • No score, no ranking. Per-check results and ratios only.

Measured 19 of 20 hosts. One host (dentsu.com) was excluded: its robots.txt disallows our user agent, so we did not request it. Two hosts were partially collected and are marked in §9.

2. Method

We sent ordinary HTTP requests with a single, honest user agent. No browser, no JavaScript, no headless renderer, no fabricated crawler identity.

User-Agent: AsReceivedAudit/1.0 (site-owner-requested verification; +https://as-received.invalid/bot)
  • Requests per host: the entry URL; the same URL with Accept: text/markdown; the .md variants of that URL; /llms.txt; and /robots.txt.
  • robots.txt is respected. Where our agent is disallowed, we do not request the path and record the host as excluded. One host was excluded on this basis.
  • Timeouts: 15 s per request at the socket level. Parallelism across hosts: 5. Wall clock for this release: 996.8 s.
  • Measurement window: 18 October 2026, Singapore time.
  • No API, no third-party packages, no server. Standard library only, so anyone can rerun it.

Six signals are recorded, each a deterministic fact about the response:

  • llms.txt — 200 and a markdown heading, or not.
  • Markdown negotiation — does Accept: text/markdown return text/markdown?
  • .md suffix — does page.md return markdown? If it returns 200 with HTML, that is recorded as a trap.
  • Vary — do both the HTML and markdown responses declare Accept? A mismatch lets an intermediate cache serve the wrong representation.
  • Payload ratio — HTML bytes divided by markdown bytes, for hosts that serve both.
  • robots.txt — the declared policy toward 13 named AI crawlers. Declarations only; we do not test response differences by impersonating them.

Rerun command. The same script and the same host list reproduce this edition:

python3 output/audit/as_received_audit.py --index output/audit/sites_2026-10-18.txt --out-dir reports/index

4. Four failure patterns

(a) The 200 that lies

2 hosts answered a request for a markdown file with 200 OK and an HTML page: 471,353B and 718,290B. A fetcher that checks only the status code puts a quarter-megabyte of markup into a context window and calls it content.

(b) Commerce does not negotiate

Of the 8 commerce hosts, 1 answered the markdown request with markdown (www.decathlon.sg, 689.8×). The rest returned HTML. The documentation hosts all answered with markdown — the capability exists, it is simply concentrated where the platforms themselves maintain it.

(c) A cache can hand out the wrong version

2 of the 6 markdown-serving hosts declare Vary differently between their HTML and markdown responses. When a cache keys on the wrong header, a browser can receive the markdown version and an agent the HTML one — for the same URL.

(d) Declared blocking

4 hosts name at least one AI crawler in robots.txt as disallowed. This is a declaration, not an observed response; we do not test response differences by impersonating crawlers.

7. One claim we withdrew

A draft of this edition said that no site published product or price structured data. On the entry URLs that was literally true — every JSON-LD block we saw was an organisation block. It was also wrong as a statement about the sites, and we are recording the withdrawal rather than deleting it.

Checking product detail pages on Shopify stores found Product, Offer and price present (allbirds $110, gymshark $15). The 19/19 figure was an artefact of measuring homepages. It appears nowhere in this edition except here, and it will not be reinstated.

8. What this report does not claim

  • Agent behaviour. We did not measure what any agent did, read, skipped or bought. Logs would be required and we do not have them.
  • Task completion, checkout success, drop-off points. Not measured, not estimated, not implied.
  • Scores, grades, ranks. None published. A single figure for a site would require a weighting we cannot defend.
  • Cross-platform AI visibility. Not measured. That is a different question, answered by other products.
  • Response differences by crawler identity. We do not impersonate crawlers. robots.txt declarations only.
  • Loss estimates. We did not model revenue or traffic impact.
  • Product detail pages. Not characterised. Homepages only.
